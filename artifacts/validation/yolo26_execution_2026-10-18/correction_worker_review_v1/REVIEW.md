# Independent correction worker review

Read-only review of `src/api/correction_worker.py`, the queue/main additions in `src/api/worker.py`, and `tests/test_correction_worker.py`. No implementation or test file was changed by this reviewer.

Two actionable findings were sent to the owning agent:

1. **Crop preprocessing diverged from the original native call.** The original extractor calls `model.predict(crop, verbose=False, device='cuda:0')`. Pinned Ultralytics 8.4.36 merges checkpoint overrides, then method defaults, then call arguments. Its method default resets confidence to 0.25, and checkpoint `imgsz` overrides previous tracking size. Inert ZIP/pickle-opcode inspection of the selected local checkpoint finds `train_args.imgsz=640`. The reviewed worker initially forced full-frame confidence 0.4 and size 960. `check_crop_resolution.py` compiles only the actual runtime's argument dispatcher and checkpoint-key filter, using a fake predictor to demonstrate 0.25/640 versus 0.4/960 without importing inference or deserializing a checkpoint.

   Other effective original crop settings are batch 1, rectangular padding enabled, FP32, maximum 300 detections, IoU setting 0.7, no augmentation, no class-agnostic NMS, and NMS disabled. The selected model remains end-to-end even though the original crop predictor argument defaults to `end2end=None`. Raw checkpoint overrides retain only image size, data, task, and single-class mode, plus model/device/task values set by loading and placement.

   The original player model has persistent tracking callbacks after full-frame `.track`. Those callbacks also run during its subsequent crop `.predict` and can filter/reorder detections across crops. A fresh bound correction predictor does not reproduce that legacy tracker contamination. The owner chose to record `DISABLED_BOUND_SOURCE_CROPS` explicitly and preserve the selected checkpoint and resolved crop preprocessing. This review does not claim the original tracking contamination has been repaired.

2. **Provider calls could be falsely reported as actual inference.** The classifier can invoke its pose provider with all selected boxes absent, and native boxes may have strictly positive but sub-20-pixel expanded crops. `_WindowBoxes` does not require an event-frame box; the actual extractor skips missing/tiny crops and returns `valid=False` without calling the model. The reviewed worker incremented provider calls before extraction and derived `new_vision_inference` from that counter. The owner was advised to count successful actual proxy predictions and require at least one for a provider call before publishing under the existing execution schema. Both all-absent and tiny-crop cases warrant regression checks.

Queue preference toggling, exclusive-lock recovery order, independent correction status, stage cancellation checks, and owner-bound publication/reconciliation have no additional actionable correctness issue identified in this review. This is a targeted review, not independent vision qualification or a GPU inference test. Actual selected-checkpoint CUDA execution remains outside the no-inference focused suite.

The historical receipt pins the exact inspected sources and selected checkpoint. `receipt.json` SHA-256: `66dd443fd21f7a90223e261f5d9f0befc4f25c8150e2647c90342515e6212391`. It records PASS for pure argument dispatch, stable source pins during that execution, and no Torch or Ultralytics module imports. Later owner fixes do not change that historical evidence.

The owner subsequently chose to retain unavailable windows and extend execution metadata with separate `pose_provider_calls` and `pose_prediction_calls`; `new_vision_inference` is derived from the latter. `check_zero_forward.py` independently executes the unchanged extracted native crop-method body, with only its `torch.no_grad` import receiving a context stub, through the actual native classifier, window gating and box validator. Both absent boxes and sub-20-pixel crops produce one provider call, zero model predictions and native UNKNOWN. The absent case reads no video frames; the tiny-crop case reads its seven eligible frames. All six source pins remain stable and neither inference runtime is imported. `zero_forward_receipt.json` SHA-256: `738267d05ca99fcb96cdd42f7c3b8c01126c9fa2fec700e7da541ee67f7b779c`. This demonstrates the legitimate zero-forward path without asserting actual model execution.
