# Native point, serve execution and rally timeline

The prior native handoff passed the final match state and every linked contact to one whole-file analytics group. A real rules-engine fixture completed two points, while the exported analytics reported one, counted second serves as first serves, included fault contacts in the live rally and replaced a known 0.970-second source interval with 0.800 seconds from frame/FPS arithmetic. The original RED remains at `artifacts/validation/yolo26_execution_2026-10-16/point_attempt_semantics_probe_v2/receipt.json`.

The selected YOLO26 path now uses `PointTimeline` and caller-owned `PointAnalysisSequence`. The legacy list APIs remain available for historical callers; preserving their old one-group behavior is not a requirement imposed on native v2 output. Native step 7 captures pre-event state, translates a physical near/far role only through a current reviewed participant binding, applies the actual rules engine and stores the explicit outcome/post-state. A missing identity mapping cannot fall back to the configured server. Missing service context produces a nullable `REVIEW_REQUIRED` line-call record before geometry.

The binding must agree with the current source frame/PTS/time base, analysis/source fingerprint, confirmed A/B track, identity epoch/revision, calibration anchor and explicit mapping/geometry references. Current production candidates have no qualified binding and retain authority-off behavior. A provider or reference string is not independent accuracy qualification. Dynamic registration still rejects event authority until that upstream upgrade is qualified.

Points preserve their own opening score, game, server and service side. First faults remain in the same point; second faults close it with the resolver's receiver winner. A service let has a distinct execution/replay index but repeats the same official first/second slot. It does not create another legal rally contact. Reviewed lets and consequential gaps enter through a separate typed, evidence-bearing rule interface; no visual let detector or new detector event enum was invented. Unknown/mid-clip/review states retain partial records and freeze confirmed advancement.

Step 9 retains the physical observations, then joins semantic membership by the source event. `is_dead_ball` continues to mean the contact occurred after the ball was already dead. A contact whose serve later faults instead gets a fault execution result and stays outside legal-rally statistics. Bounce associations crossing point/attempt/review/dead boundaries are cleared, including derived direction. `shot_play_scope.json` distinguishes these observations. A point's `shot_ids` audits all its contact observations; rally IDs contain legal-rally contacts, and the exported membership scope states that distinction.

Step 10 exports version-2 point/rally records and serve executions from indexed selections. Per-player serve statistics distinguish contact executions, official slots, lets, resolved first/second outcomes, double faults and unresolved execution coverage. First-serve percentage is in / (in + fault) for resolved official first slots; it is null without a denominator. Playing time reports the sum of known completed-rally durations with its measured-rally count and complete-rally denominator. It does not fill unknown durations with zero or imply that excluded portions were measured.

Rally duration subtracts exact rational source clocks at the legal serve contact and actual terminal event. Every intervening source edge must retain reviewed normal-speed eligibility, ordering, camera segment and calibration anchor. Time-base changes and large offsets are evaluated as fractions before float conversion. Source-playback elapsed time is separately labeled; it cannot substitute for verified physical playing time. A missing/reversed clock, cut, reanchor or unsupported interval withholds full duration. The native HUD queries the latest indexed state through the current frame instead of painting the final score backwards.

The ledger keeps one active point, attempt and rally in Python; snapshots and memberships live in SQLite with a 2 MiB cache, mmap disabled and commits bounded to 256 mutations. Readers and exact owned files/sidecars close on success, failure and cancellation. Indexed views preserve full records for iteration, indexing and slicing. UIDs bind analysis identity, source fingerprint, revision and event anchor. Exact retries require a canonical fingerprint of the raw physical/reviewed input and complete context; a changed payload or proof cannot reuse a cached outcome. Active-point identity/calibration/mapping proof changes freeze progression until an explicit reviewed revision. Same-frame rule inputs merge by source timestamp/event ID; ambiguous shared identities and reversed order fail.

Its fixed cache is 2 MiB, mmap is off, temporary operations use files and ordinary batches commit within 256 writes. Correction replay reads one old input at a time into a staged revision, retains old audit history on disk and publishes on clean transaction exit. A correction remains one full disk transaction; retained revisions and transaction disk usage can grow. History JSON streams current and nested prior histories atomically without constructing all-input/all-history Python lists. Default legacy callers retain their original list behavior.

An event write failure restores both the current rule state and resolver. An uncertain ordinary or correction COMMIT invalidates the complete journal: later reads, writes, state/history export and retries fail, preserving their previous destination files. This avoids continuing with state ahead of lost rows, or an old engine against a correction that committed before its error was observed. Normal pre-publication replay failures roll back without replacing the active revision. Owners close suspended readers and remove only their exact scratch files; cleanup cannot mask the caller's primary failure. ## Saved web result extension, 17 October

`publish_point_timeline_manifest` atomically seals the eight native artifacts after export: point analytics, rallies, match analytics, serve executions, shot play scope, scoring events, score history and match state. It binds source SHA256, analysis identity/revision, scoring revision zero, authority state and each artifact's bytes/SHA256. This manifest does not atomically publish the complete analysis or video. A corrected scoring revision still requires rebuilding all derived output; the publisher and reader reject nonzero scoring revisions until that workflow exists.

`load_point_analysis` validates the manifest/source, all eight complete artifacts, IDs and cross-references, source contexts, actual serve denominators and summary totals. It indexes the actual `match_events.json` on disk with a capped 2 MiB SQLite cache. Each non-reviewed transition must consume one unique physical event with matching ID, frame, type and exact normalized timestamp; reviewed rule transitions require a supported kind, nonblank reference and no physical ID collision. Every physical event must be consumed. Authority-off output must contain neither physical nor rule transitions. Before/after hashes reject publication races. The eight-file manifest does not include the physical artifact; the reader separately hashes that artifact before and after reading. A digest binding all unrounded raw physical payload fields remains future work.

The optional result field is `pointAnalysis`, schemaVersion `1.0`, with literal `status: UNQUALIFIED` and `independentAccuracyValidated: false`. No manifest flag can enable confirmed scoring. It contains `analysisId`, `analysisRevision`, `scoringRevision`, `sourceSha256`, `authoritativeEventsEnabled`, `summary`, `serveByPlayer`, `points`, `rallies` and `serveExecutions`. The worker uses ResultStorage disk series for growing arrays. Legacy output without the extension remains valid; a present invalid extension is withheld with a section warning.

| Result member | Meaning |
