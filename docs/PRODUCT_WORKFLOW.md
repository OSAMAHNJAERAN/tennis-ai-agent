## Start

Use the existing project Python environment with the installed model dependencies, and Node 22+. Install the existing frontend dependencies with `pnpm install --frozen-lockfile` from `frontend/` if needed. FFmpeg and ffprobe must be on PATH (or use the overrides below).

Build the website once, then serve the website and API together:

```powershell
# In frontend/
pnpm build
# From the repository root, using the ML Python environment:
python scripts/run/serve_product.py
```

Open [the local website](http://127.0.0.1:8000/). Choose **Upload match**, select or drop an MP4, MOV or AVI, and click **Analyze match**. The upload shows byte progress; analysis shows the current stage, not an invented completion percentage. Open a completed session to explore source playback, 2D/3D court replay, player motion, heatmaps, measured statistics and downloadable annotated video/JSON. The **Annotated AI video** disclosure provides rendered playback. Historical demos remain available in the session picker.

For frontend development, run `pnpm dev` in `frontend/` and `python -m uvicorn src.api.app:app --host 127.0.0.1 --port 8000` from the repository root. Vite proxies `/api` to the backend. Coach configuration still uses the existing `ASTRA_GPT_*` environment variables; see `ASTRA_TENNIS.md`.

## Processing and storage

- The API streams the raw video request body with a bounded byte count and checks the filename extension and container signature. The worker checks video metadata, then fully decodes/transcodes it before inference. The default limit is 1 GiB, 120 FPS, two hours and 3840 × 2160 pixels. The duration and upload-byte limits can be configured.
- IDs are random `match_<32 hex characters>` values. Client filenames are display metadata, never filesystem paths. Original uploads are stored in `outputs/product/uploads/<id>/original.<extension>`.
- SQLite at `outputs/product/analyses.sqlite3` records upload, processing, completion or failure, stage, timestamps and sanitized errors. One worker holds an OS-backed file lock, serializing GPU inference. It runs separately from HTTP, so accepted work continues through web-server restarts. Another server process cannot recover or claim the active worker's job while that lock is held.
- For selected native YOLO26 ball processing, worker startup can resume the same analysis after a sealed complete player/court/identity pass and a partial raw-ball frontier. It reuses sealed normalized video, source clock, metadata and configuration; validates original/config/model/runtime/source identities and the explicit saved device; skips completed player/court inference; and commits one complete full-frame-plus-tile ball result at a time. Filters and downstream analysis/rendering rerun globally from fresh scratch. Interrupted player tracking has no partial-state restore. Missing/corrupt/unsealed state, cancellation and exhausted attempts are ineligible; at most two automatic continuations follow the initial attempt. Retry creates a new analysis from the retained original.
- A completed-stage checkpoint takes precedence and resumes finalization after the whole pipeline has returned. It verifies all required/optional artifacts, then prepares browser video, checks decoded frame counts and publishes the result before completion. Normalized-source seals are rechecked before publication for native executions that use them; older complete-stage-only checkpoints retain their contract. The current **485-check software scope** includes actual process loss/restart, real FFmpeg and the native worker/pipeline/result publication on an **eight-frame synthetic video with injected model results**. Its two recovery cases cover exit after a raw commit and inside a ball tile, each showing one normalization, suffix-only ball calls and matching outputs against a continuous run; the tiled case also preserves an empty raw frame. Actual selected-model, long-match, independent accuracy and live qualification remain pending. See [the recovery contract](plans/NATIVE_INFERENCE_RESUME.md).
- The native candidate finishes the complete player-tracking pass before reusing the same selected model for body crops, with fixed checkpoint preprocessing and admitted device. Crop failures stop publication; actual/completed prediction counts remain in metrics. A fresh sequential decoder discards saved prefix frames without forwarding them or using approximate seek. Durable prefix/raw journals and seal staging files remain private retained diagnostics; include them when planning storage and backups.
- Outputs and detailed `processing.log` are stored in `outputs/product/analyses/<id>/`. Invalid/failed output is never published as a completed run. Raw uploads and completed results are retained; back up this directory as one unit. Failed/disconnected requests clean up their own temporary files. Hard process termination during an upload may leave an orphan `upload.part`; it is not a queued job and can be removed by the operator after confirming no upload is active.
- `source.mp4` is H.264 at constant frame rate for deterministic playback and inference. The uploaded original is retained separately. Normalization follows source presentation time and duplicates/drops frames for variable-rate inputs; all inference timestamps refer to the normalized timeline. Audio is omitted from analysis playback; the original download retains it. No audio analysis is claimed.
- `annotated.mp4` is the existing pipeline output; `annotated_web.mp4` is its H.264 browser copy. Both browser videos are decoded and frame-count checked before publication. HTTP byte ranges support playback seeking.
- Completed native analyses publish an immutable generation containing the result database, original upload, media and analysis artifacts. The result supplies generation-bound replay/export links; use those links to keep a viewed report and video consistent. Previous committed generations remain available to the owner. Files missing from a generation are unavailable instead of being replaced by mutable current files. The worker rechecks cancellation and input/checkpoint identity after copying, directly before committing the current pointer. Historical saved analyses remain readable.
- Public examples select an explicit generation. A newer private revision does not update the public example automatically, and removing its curation entry revokes visitor access. Generation storage makes independent copies of media and retains history and failed diagnostics: include these in disk-capacity planning and backups. No automatic expiry/deletion policy is implemented by this change.
- `run_config.yaml` and the per-job config retain the existing model recipe and unique match ID. No training, model replacement or accuracy promotion is performed.

## Resumable uploads and batches

`POST /api/uploads` accepts `{filename,size_bytes,match_id?,batch_id?,clip_index?,start_offset_seconds?}` and saves an upload session. The filename is display metadata. `GET /api/uploads/{id}` returns its persisted byte offset after refresh or server restart. Append raw bytes using `PATCH /api/uploads/{id}` with the exact `Upload-Offset` header, at most 8 MiB per chunk. Read the current offset after a conflicting response; never blindly repeat uncertain chunks. Completion is `POST /api/uploads/{id}/complete`, returning a 202 analysis job after the declared byte count and container signature pass. Repeated completion returns the same job. The session's `analysis_id` remains null until acceptance. `DELETE /api/uploads/{id}` cancels staging and removes only its owned partial upload.

`POST /api/batches` accepts `{mode,files:[...]}`, up to 16 files, using the upload specification above. Each file has independent transfer and processing state. An invalid container saves its transfer as `FAILED` with a sanitized error, surviving refresh while other files proceed. Modes are `independent` or `same_match`; the latter requires explicit unique `clip_index` values from zero to file count minus one. Optional offsets are nonnegative finite seconds and user-supplied grouping metadata. `GET /api/batches/{id}` persists each transfer, job and SHA256. Exact duplicate files are identified. Unified match reports remain unavailable until continuity, order and partial-overlap evidence are independently verified; grouping itself never establishes that clips can be merged.

`POST /api/analyses/{id}/cancel` immediately fails queued work with `cancelled:true`. Processing work sets `cancel_requested`; the worker exits at an existing safe stage boundary and withholds publication. Cancellation may wait for the current long stage. `POST /api/analyses/{id}/retry` uses the retained original to create a new job, linked by `retry_of`, without uploading it again. The exclusive worker lock and transactional claims prevent duplicate active claims on this host. Stage heartbeat timestamps are diagnostic; they are not a distributed lease or frame-checkpoint resume implementation.

## Data contract and limits

The result adapter reads Phase 6 exports and maps `player_motion.json` to frame-aligned ground paths and speed samples. It retains confidence, camera-loss gaps and nullable values. Required invalid metadata/trajectory frames fail publication. Optional malformed dashboard sections show **Analysis unavailable for this section** while valid sections remain accessible.

Ball speed, bounce placement, rally/shot statistics and scoring remain unavailable when the selected pipeline withholds them. Two-dimensional ball projection is not measured three-dimensional flight. Player IDs are near/far roles, not recognized names; speed and distance are estimates over observed contiguous intervals. Court reprojection residual is fit consistency, not independent court accuracy. Uploaded sessions never inherit the illustrative player rankings, names or match statistics from legacy showcase pages.

Saved native output may additionally expose a **Points in context** section through optional `pointAnalysis`. Its manifest/source/revision and physical-event correspondence must validate before it is published. The section shows provisional point records, first/second serve attempts, lets, double faults, legal-rally counts and known source-time durations with coverage. Reviewed participant A/B identity is separate from local court roles. An absent duration is shown as unavailable; a double fault has no legal rally duration. Withheld event authority shows unavailable outcomes instead of treating zero exported records as zero actual play. These records remain explicitly unqualified and do not enable confirmed automatic scoring.

New native runs also retain private `native_rule_replay.json`, required by the completed-stage worker seal. It preserves raw rule inputs, source/identity continuity and original shot linkage. The new owner correction workflow uses that sealed evidence to rebuild dependent analytics, reports and annotated media together. It is undergoing integration and integrity verification; independent measurement qualification remains incomplete. Existing manual-match score editing is separate; recorded line calls cannot be reused after a context-changing correction without recomputation or explicit review.

A private developer correction helper replays existing source-bound inputs with a reviewed initial state or semantic/binding amendments and computes fresh line calls using each event frame's geometry. Following helpers relink physical shots, rebuild native point/serve/rally statistics and recompute causal statistical forecasts from exact raw score states. A private exporter regenerates semantic files, fresh landing zones, forecasts and the exact admitted command in a unique twenty-file set. Strict point/landing readers and reproduction of its new rule replay must succeed before the final hash seal is returned. Source media is copied independently; earlier candidates remain intact and failed candidates have no final seal. These are private exports; the committed analysis is unchanged. Forecast history and point identities remain on disk. Forecasts keep an explicit uncalibrated neutral prior and withhold results for unknown, unanchored or contradictory score context. Landing display needs explicit unchanged source contact review/uncertainty and fresh accepted geometry; line confidence and mutable display fields cannot supply qualification. Reachable configured crop-pose branches still require a trusted selected-player provider.

A following private renderer now starts from that sealed source and produces new native and browser videos. Score and uncalibrated prediction text use their actual frame prefix. New accepted calls, live/dead shots and current-frame contact polygons replace original semantics; image roles/proxies are labeled and unqualified world positions remain unavailable. Source/camera/identity barriers prevent highlights and trails crossing cuts. Unrenderable projective geometry is withheld for its frame and counted without rewriting source/call evidence or discarding the rest of the video. The exporter hash, live event mutation generation, artifact hashes and full source/native/browser decode checks must pass before its separate seal is returned. Independent review closes optical-event mutation and sealed/live-event inconsistencies.

Private result preparation now joins those videos and fresh semantics with independently copied sealed observations and the original upload. Its owned disk result streams matching JSON, self-contained HTML with evidence images, and CSV; an independently replayed forecast history remains explicitly uncalibrated and keeps unknown gaps. Original inference provenance and analysis metadata come from the sealed base result, with unavailable provenance identified rather than recomputed from current weights. The private review records the new revision, human dependence and correction date, while explicitly withholding authenticated/publication status. Source/copy/report hashes and both lazy result/root values must remain consistent throughout consumption. A default candidate has 49 files; the four optional observation files and a fresh valid derivative credit make 54. The original source credit stays preserved, while JSON/HTML/CSV describe the new derivative consistently. Failures remove only the candidate seal and preserve previous complete candidates and the committed analysis.

These private stages now feed a separate durable correction lifecycle. Only the analysis owner can read paginated source review evidence or submit an amendment; account mode derives reviewer identity from its cookie session, while explicit loopback local mode records that different authorization method. Commands bind the original source, replay digest, generation, revision and per-event fingerprints, with a one-MiB/128-amendment limit. Stable command IDs make a lost submission acknowledgement safely retryable.
