# Court heatmap candidate: broadcast control and viewpoint failure

## Motivation and source

Two ResNet coordinate regressors failed the side-camera and ground-level probes, sometimes producing internally consistent but visibly wrong court fits. A spatial heatmap model provides a distinct localization architecture and explicit missing landmarks. The [author's TennisCourtDetector repository](https://github.com/yastrebksv/TennisCourtDetector) was inspected at commit `e5cd4f1ce26b15361700d3d89e068cbf0e82749e`, preserved under `artifacts/research/TennisCourtDetector`. The author describes broadcast-video training, fifteen output heatmaps (fourteen court points plus court center), and a single640x360 image input. Its training images were generated by classical detection and manual filtering. These are publisher descriptions, not independent evidence of camera generalization.

The42,312,975-byte author-linked Google Drive checkpoint was acquired with exact response-size checks. Local SHA-256: `09aa8c4338459ba1d643f2dc329f45f464dedec3720fccc1a4abfd1f7b464d04`. The publisher did not supply an independent digest. Provenance is retained in `artifacts/models/court/heatmap_research/provenance.json`; binary weights are ignored by the existing *.pt rule. No explicit source license was found; this isolated research benchmark does not establish a production redistribution grant.

## Faithful inference with native coordinate adaptation

`scripts/evaluate/benchmark_court_heatmap_probe.py` imports only the inspected architecture module and strictly loads the state dictionary with `torch.load(weights_only=True)`. It uses the author's OpenCV BGR input, linear resize640x360, float32/255, and sigmoid outputs. The first fourteen channels follow the inspected court-reference order. No RGB conversion or ImageNet normalization is substituted.

Published image-inference postprocessing is retained: uint8 heatmaps, binary threshold170, HoughCircles dp1/minDist20/param1=50/param2=2/minRadius10/maxRadius25, first circle returned. The author's fixed scale2 assumes1280x720 output. The benchmark instead maps x by native_width/640 and y by native_height/360 so640x360 UVY and1920x1088 CalTennis outputs are represented correctly. Missing channels remain None. No line refinement, homography reconstruction, argmax fallback or threshold tuning is used. Full heatmaps, all Hough candidates, peak values and native coordinates are saved for subsequent analysis.

The strongest UVY output was visually inspected. Some detected points coincide with visible line intersections on the right half of the court, but keypoint roles are inconsistent (multiple baseline/side identifiers cluster on the same half). This is not a recovered court. Counts alone do not show correct point identity or accuracy. Other previews are retained; they have not all been visually reviewed. The candidate fails to supply a usable complete court on these views at its published operating point.

## Broadcast positive control

A subsequent control uses the first frame of every clip in the already acquired six-clip RacketVision validation set: match138,139,14,140,141,142. These were selected as a complete existing set, not by heatmap predictions. The first control attempt stopped before inference because its older manifest has no `complete` field. That empty output directory is preserved. The wrapper now explicitly checks the legacy validation-only schema, expected six videos, and every recorded file hash. The corrected control completed in `outputs/vision_upgrade_audit/court_heatmap_broadcast_control_verified/report.json`.

All six frames return14/14 landmarks with the same checkpoint, preprocessing and Hough settings. The match138 overlay was visually inspected and closely follows visible court lines. This confirms useful localization on an expected broadcast view; it does not establish quantified accuracy, all-six visual correctness, training independence or generalization. There are no independent court GT labels in these six clips. The control wrapper adds dataset selection and legacy-manifest support; its saved script hash differs from the earlier challenging-view run, while the model/source hashes and inference settings are unchanged.

## Decision and next work

Do not promote this candidate as a camera-general replacement. Its broadcast control makes the sparse ground-level result more consistent with domain failure than a completely broken loader/preprocessing path. The result supports training and evaluating a spatial model with explicit viewpoint diversity and visible-landmark supervision. Merely lowering the heatmap threshold or fitting a homography to incorrectly assigned points would not address landmark identity.

CalTennis currently provides useful projection hypotheses, but its exact image transform and court-coordinate template remain unverified. Those projections must not silently become training labels or independent evaluation truth. Establish reviewed visible court landmarks and disjoint camera/session evaluation before claiming a trained improvement. Ball speed and event authority remain unavailable.
