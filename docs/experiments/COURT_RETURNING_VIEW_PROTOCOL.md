# Original-view court registration recovery

Frozen 2026-09-14 before real-image evaluation. Existing CourtCameraRegistration latches a failed registration for all remaining frames. An optional wrapper will recover only correspondence to the original anchor when it returns, keeping the original court calibration and existing optical-flow/RANSAC/coverage gates. This does not detect or calibrate a new court and cannot repair a wrong initial landmark fit.

After a failed frame, withhold coordinates immediately. Probe the next frame against the original anchor; after a failed probe wait ceil(.5*FPS) frames. Once a probe passes, check every subsequent frame and require max(3,ceil(.1*FPS)) consecutive passing frames before publishing coordinates. A failed confirmation resets the streak. Keep all prior failed/pending frames missing. Preserve a global frame index and recovery-segment identifier in audit output. No model download/training or parameter tuning on the test images.

Use deterministic synthetic textured images for known translation/projective recovery, unrelated scenes, interrupted confirmations, invalid anchors and bounded retry behavior. Verify unchanged healthy output against the existing implementation. Then replay fixed source frames from the completed match148 run: original frames 0-59, a 30-frame cut made from a different known court recording, and original frames 60-119. Also include a blank cut, permanent unrelated view, a two-frame brief return and a healthy 120-frame control. Original per-frame player detections mask foreground where available; unrelated view uses its saved detections. All source frames and annotations are existing development material, and splices are controlled challenges, not natural-cut qualification.

Measure valid/withheld frames, recovery delay, false accepts during unrelated intervals, and agreement with the unchanged anchor registration on the returned source frames. Preserve every frame audit, source hashes and the fixed frame map. Require no accepted unrelated/cut frames, no premature two-frame restoration, no changed healthy calibration, and recovery on a sustained original return before enabling an opt-in pipeline config. Validate actual pipeline exports separately. Runtime defaults and physical/event authority remain unchanged; broad independent camera recovery is unproven.
